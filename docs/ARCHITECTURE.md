# 神经层级深度融合统一多模态模型 —— 架构设计

> 代号：**NF-1（Neural Fusion v1）**
> 目标：把 GPT-OSS-20B（语言主干）+ Qwen2.5-VL-7B 的 ViT（视觉塔）+ FLUX.1-Schnell（DiT 生成头）融成**一个网络内部的信息流**，而不是三个模型轮着调度。
> 本文只描述「怎么搭」，训练流程见 `TRAINING.md`，导出见 `EXPORT.md`。

---

## 0. 先说清楚一件事：什么叫「真正的融合」

「融合」有三个层次，别混：

| 层次 | 做法 | 是不是你要的 |
|---|---|---|
| L0 调度 | 三个模型各自跑，用代码把结果串起来 | ❌ 你明确否掉了 |
| L1 特征级 | 视觉特征投影进主干词向量空间，同一注意力里算；生成用主干隐状态驱动 DiT | ✅ **本设计走这条** |
| L2 权重级 | 三个模型的所有权重物理合并成一个 `.safetensors` 文件 | ✅ 本设计也做（见 EXPORT.md） |

L1 是「神经层融合」，L2 是「文件层合并」。两者不冲突，都要做。

**关键判断：L1 能做到「同一隐空间 + 同一注意力流」，但做不到「三个模型的权重互相改」**——因为三者的层数、宽度、归一化方式都不同。所以融合点只有两处，必须在架构图上标死：

1. **输入端**：视觉 token 投影到主干的 `hidden_size=2880` 空间，和文本 token 拼成一条序列，一起进主干的 24 层 Transformer。
2. **输出端**：主干最后一层的隐状态，投影成 DiT 的文本条件向量，直接喂给 FLUX 的 cross-attention。

这两处就是「神经接线」。接好了，就是一个模型；接不好，就还是调度器。

## 2. 分层张量维度清单（每一层都写死）

### 2.1 视觉塔（Qwen2.5-VL-7B 的 ViT，冻结）

| # | 层 | 输入 shape | 输出 shape | 参数量 |
|---|---|---|---|---|
| V1 | Patch Embed | `[B,3,H,W]`, H=W=448 | `[B, 1024, 1280]` | 14×14 卷积，patch=14 |
| V2 | 2D RoPE 位置编码 | `[B,1024,1280]` | `[B,1024,1280]` | 0（频率表冻结） |
| V3 | ViT Blocks ×32 | `[B,1024,1280]` | `[B,1024,1280]` | ~0.3B |
| V4 | Merger（2×2 空间合并 + MLP） | `[B,1024,1280]` | `[B,256,3584]` | ~17M |

> 说明：448×448 输入 → 32×32 patch 网格 = 1024 个 visual token；merger 做 2×2 合并 → 256 token；每 token 3584 维（这是 Qwen2.5-7B 的 hidden）。

### 2.2 视觉连接器（**本设计新增，可训练**）

| # | 层 | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| C1 | LayerNorm | `[B,256,3584]` | `[B,256,3584]` | 稳定分布 |
| C2 | Linear | `[B,256,3584]` | `[B,256,2880]` | 对齐到主干宽度 |
| C3 | GELU | — | — | 非线性 |
| C4 | Linear | `[B,256,2880]` | `[B,256,2880]` | 残差投影 |
| C5 | LayerNorm | `[B,256,2880]` | `[B,256,2880]` | 输出前归一 |

参数量：`3584×2880 + 2880×2880 ≈ 18.6M`（FP16 约 37 MB，可训练没问题）

> ★ 这一层**就是「神经接线」**。它的唯一任务：让视觉特征落入 GPT-OSS 词向量的同一分布。训练目标只有一个——让主干「看懂」。

### 2.3 主干（GPT-OSS-20B，大部分冻结）

| # | 层 | shape | 说明 |
|---|---|---|---|
| M1 | Token Embedding | `[B,L]` → `[B,L,2880]` | vocab=201088 |
| M2 | Transformer Block ×24 | `[B,L,2880]` → `[B,L,2880]` | 每层：GQA(64头/8 KV头, head_dim 64) + RoPE(theta=150000) + MoE(32专家,top-4) |
| M3 | Final Norm | `[B,L,2880]` | RMSNorm |
| M4 | LM Head | `[B,L,2880]` → `[B,L,201088]` | 输出文本 logits |

> 主干里序列长度 L = 文本 token 数 + 视觉 token 数（256）。拼接顺序按 ChatML/Harmony 模板：`<|start|>user<|message|>[视觉256]<文本>...`

### 2.4 生成头连接器（**本设计新增，可训练**）

| # | 层 | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| G1 | 取主干最后隐状态 | `[B,L,2880]` | `[B,L,2880]` | 只取「生成指令」那段的最后 token |
| G2 | Linear | `[B,2880]` | `[B,4096]` | 对齐 FLUX 的 T5 条件维度 |
| G3 | LayerNorm | `[B,4096]` | `[B,4096]` | |
| G4 | 序列化（可选） | `[B,4096]` | `[B,77,4096]` | 复制/广播成 77 个 token，匹配 FLUX 的序列长度 |

参数量：`2880×4096 ≈ 11.8M`

### 2.5 DiT 生成头（FLUX.1-Schnell，只训适配）

| # | 层 | shape | 说明 |
|---|---|---|---|
| D1 | 输入投影 | `[B,16,64,64]` → `[B,4096,3072]` | patchify latent（16 通道，8× 下采样） |
| D2 | 双流 MMDiT ×19 | `[B,4096,3072]` | 图像流 + 文本流各自 attention，再交叉 |
| D3 | 单流 MMDiT ×38 | `[B,4096,3072]` | 两流合并 |
| D4 | 3D RoPE | — | 图像 (h,w) + 文本位置，**独立频率表** |
| D5 | 输出投影 | `[B,4096,3072]` → `[B,16,64,64]` | 预测速度场 v |
| D6 | VAE Decode | `[B,16,64,64]` → `[B,3,512,512]` | 冻结 |

## 3. 数据流走向（完整一次前向）

### 3.1 图文输入 → 文本回答

```
输入: image(448×448) + text("这图里是什么枪？")
  │
  ├─► ViT: [1,3,448,448] → [1,1024,1280] → merger → [1,256,3584]
  ├─► Connector: [1,256,3584] → [1,256,2880]   ★可训练
  ├─► Text Embed: [1,n] → [1,n,2880]
  ├─► Concat: [1, 256+n, 2880]     ← 视觉 token 在前，文本在后
  ├─► GPT-OSS 24层: [1,256+n,2880] → [1,256+n,2880]
  ├─► LM Head: → [1,256+n,201088] → 采样 → "这是 AK-47..."
  └─► 输出文本
```

**这一步就是「神经融合」的证明**：视觉 token 和文本 token 在**同一组注意力头**里互相看，不是先描述再回灌。

### 3.2 文本指令 → 图像生成

```
输入: text("画一把赛博朋克风格的霰弹枪")
  │
  ├─► Text Embed → GPT-OSS 24层 → 最后隐状态 [1,2880]
  ├─► GenHead Adapter: [1,2880] → [1,77,4096]    ★可训练
  ├─► FLUX MMDiT: latent噪声[1,16,64,64] + 条件[1,77,4096]
  │     4 步 Euler（Schnell 蒸馏版）→ [1,16,64,64]
  ├─► VAE Decode → [1,3,512,512]
  └─► 输出图像
```

### 3.3 图生图（最关键的一步）

```
输入: image + text("把背景换成雨天")
  │
  ├─► ViT+Connector → 视觉 token → GPT-OSS → 理解「要改什么」
  ├─► GPT-OSS 隐状态 → GenHead Adapter → 条件向量
  ├─► VAE Encode(原图) → latent [1,16,64,64]
  ├─► 加噪到 t=0.6 → 去噪 4 步（条件 = 上面的向量）
  └─► VAE Decode → 新图
```

**注意**：图生图不是「重新生成」，而是「在主干理解后的条件下去噪」。这是融合架构相对调度架构的核心优势——**改图时模型真的「知道」原图是什么**。

## 4. 维度对齐方案（硬骨头在哪）

### 4.1 三个必须对齐的维度

| 边界 | 源维度 | 目标维度 | 方案 | 是否可训 |
|---|---|---|---|---|
| ViT → 主干 | 3584 | 2880 | 2 层 MLP + LN | ✅ |
| 主干 → DiT 条件 | 2880 | 4096 | Linear + LN | ✅ |
| latent 通道 | VAE 16ch | DiT 16ch | 原生一致，无需改 | — |

### 4.2 RoPE 怎么办（你要求「统一对齐」）

**诚实说：RoPE 不能跨模态共享，只能统一实现 + 各自独立频率表。** 原因是位置语义不同：

| 模块 | 位置语义 | RoPE 类型 |
|---|---|---|
| GPT-OSS | 1D 文本位置 | 1D RoPE, head_dim=64, theta=150000 |
| ViT | 2D 图像网格 (h,w) | 2D RoPE, 分给 h/w 两半 |
| FLUX DiT | 2D latent + 1D 文本 | 3D RoPE（含时间轴） |

**统一对齐的工程做法**：
1. 抽出一个公共的 `RotaryEmbedding` 类（同一套频率计算公式、同一 dtype、同一数值精度）。
2. 三个模块各自实例化，**频率表不共享权重**（共享了反而破坏预训练）。
3. 视觉 token 插进主干序列时，**沿用主干的 1D 位置编号**（视觉 token 占据 0..255，文本从 256 开始）——这才是真正需要对齐的地方。

> 一句话：RoPE 的「实现」统一，「频率表」各自保留，「序列位置编号」在融合点统一。

### 4.3 归一化对齐

| 模块 | Norm 类型 | eps |
|---|---|---|
| GPT-OSS | RMSNorm | 1e-5 |
| ViT | LayerNorm | 1e-6 |
| FLUX | RMSNorm（在 DiT 内） | 1e-6 |

**做法**：不改原模块的 Norm（会破坏预训练），只在**连接器输出端**加一个 LayerNorm 把分布拉正。这就是为什么 Connector 的 C5 和 GenHead 的 G3 都带 LN。

## 5. 权重加载方案

### 5.1 加载顺序（必须按这个顺序，否则显存峰值会炸）

```
1. 先加载 ViT（0.3B，~1.2GB FP16）       → 冻结
2. 再加载 Connector（18.6M，~37MB）       → 可训练，随机初始化
3. 再加载 GPT-OSS-20B（4bit NF4，~11.3GB）→ 冻结，挂 LoRA
4. 再加载 GenHead Adapter（11.8M，~24MB） → 可训练
5. 最后加载 FLUX DiT（4bit，~6.5GB）      → 冻结，挂 LoRA
6. VAE 单独加载（~330MB）                 → 冻结，只在 encode/decode 时用
```

### 5.2 分阶段加载（32GB 内存的关键）

推理时**不要一次全装**：

| 阶段 | 驻留 | 内存 |
|---|---|---|
| 纯聊天 | 主干 4bit | 11.3 GB |
| 看图 | 主干 + ViT + Connector | 12.5 GB |
| 画图 | 主干 + GenHead + DiT(4bit) | 18 GB |
| 图生图 | 主干 + ViT + DiT | 18.5 GB |

> 这是「运行内存 ≤ 24GB」目标的落点：**任何时刻不同时驻留 ViT 和 DiT**，它们只在「图生图」时需要短暂共存（此时可以临时把主干卸载——但那是 L0 做法，本设计用 4bit + 分块加载避免）。

### 5.3 4bit 量化配置

```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,   # 二次量化，再省 0.4GB
)
```

## 6. 训练策略（QLoRA，三层冻结/可训）

### 6.1 冻结 / 可训练清单

| 模块 | 状态 | 参数量 | 说明 |
|---|---|---|---|
| ViT | ❄️ 冻结 | 0.3B | 视觉特征已足够好，别动 |
| GPT-OSS 主干 | ❄️ 冻结（4bit） | 20B | 保住代码/推理能力 |
| 主干 LoRA | 🔥 可训 | ~40M (r=64) | 只挂 attention 的 q/k/v/o |
| Connector | 🔥 可训 | 18.6M | 核心接线 |
| GenHead Adapter | 🔥 可训 | 11.8M | 生成接线 |
| FLUX DiT | ❄️ 冻结（4bit） | 12B | |
| DiT 适配 LoRA | 🔥 可训 | ~60M (r=64) | 只挂 cross-attention 的 k/v |

**总可训参数 ≈ 130M**（占全模型 0.4%），这就是「最大限度保住主干能力」的兑现。

### 6.2 训练三阶段（不要一次训）

| 阶段 | 训什么 | 数据 | 显存 | 时间（A100 80G） |
|---|---|---|---|---|
| **S1 对齐** | 只训 Connector | 图文对 50 万 | ~22 GB | 8 小时 |
| **S2 生成** | 只训 GenHead + DiT LoRA | 文生图 30 万 | ~35 GB | 15 小时 |
| **S3 联合** | Connector + GenHead + 双 LoRA | 图文 + 文生图 + 图生图 | ~45 GB | 30 小时 |

> S1 用「冻结主干、只训 projector」是 LLaVA 的成熟套路，能快速验证接线对不对；S2 单独训生成头；S3 才联合。

## 8. 这份设计的边界（不吹牛）

| 能做到 | 做不到 |
|---|---|
| 视觉 token 和文本 token 在同一注意力里融合 | 三个模型权重在训练时互相更新 |
| 主干隐状态直接驱动 DiT 生成 | RoPE 频率表跨模态共享 |
| 单文件导出（safetensors 合并） | 32GB CPU 上快速跑 DiT（FLUX 12B 在 CPU 上极慢） |
| 4bit 下总驻留 ≤ 24GB | 本机训练（无 GPU，必须云租） |
